# bw_timex

`bw_timex` makes a Brightway calculation use the right data for the right point in
time. A normal LCA evaluates the whole supply chain with data for a single moment, but
a long-lived product is built with one year's technology, used across many years of a
changing electricity mix, and disposed of with the technology of a later year
(source: bw-timex-docs).

You bring a normal Brightway model plus two extra ingredients: temporal distributions
saying when each exchange happens relative to the process consuming it, and
time-specific process data, such as background databases representing different years.
`bw_timex` works out when every process in the supply chain actually happens, relinks
each one to the background database matching that date, interpolating between databases
in between, and applies the time-specific amounts. The result is a time-explicit
inventory in which each emission is tagged with when it happens, so it can be
characterised dynamically rather than with a static factor
(source: bw-timex-docs).

It is most useful for long-lived products, strongly evolving production systems and
biogenic carbon (source: bw-timex-docs).

## Install

```bash
pip install bw_timex==1.4.0
```

`bw_timex` depends on Brightway 2.5 and pulls bw25-compatible versions of the Brightway
packages, so it **cannot** be added to a Brightway 2 environment, including one holding
Activity Browser 2 (source: bw-timex-docs). See
[../activity-browser/gotchas.md](../activity-browser/gotchas.md).

Optional extras: `[solvers]` for the macOS solver stack, `[premise]` for building
prospective background databases. The documentation recommends giving `[premise]` its
own environment, because premise pins numpy below 2 and would downgrade numpy and scipy
in a working bw_timex environment (source: bw-timex-docs).

On conda the package is noarch, so `pypardiso` is not pulled in automatically and has
to be named explicitly (source: bw-timex-docs). See
[../pypardiso/README.md](../pypardiso/README.md).

## What it does

- **Builds a process timeline.** Graph traversal with temporal distributions produces a
  timeline of dated processes. See [classes.md](classes.md).
- **Relinks to time-specific databases.** The matrix modifier inserts time-explicit
  copies of processes and wires them to the right background vintage, interpolating
  between the two nearest. See [classes.md](classes.md).
- **Calculates a time-explicit inventory.** `TimexLCA.lci` builds a dynamic biosphere
  matrix whose rows are flow-and-date pairs. See [commands.md](commands.md).
- **Characterises statically or dynamically.** `static_lcia` uses ordinary
  characterisation factors, `dynamic_lcia` uses characterisation functions over a time
  horizon. See [classes.md](classes.md).
- **Compares configured runs.** `TimexLCA.compare` runs several settings objects and
  collects them into one table. See [commands.md](commands.md).

## Datasets

`bw_timex` ships no inventory data. It does ship one reference data file: a set of
decay multipliers keyed by CAS number, used by the dynamic characterisation path to
turn an emission at a date into radiative forcing over the following years. It also
ships a function that builds a small illustrative electric vehicle product system in a
Brightway project. [datasets.md](datasets.md) describes both, structure only.
