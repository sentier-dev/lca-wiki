# sentier-agribalyse

sentier-agribalyse imports the public Agribalyse 3.2 SimaPro export, links it to a
licensed background database through a tiered mapping registry whose tiers are data
rather than code, registers the headline EF 3.1 impact assessment methods, scores every
product, and backtests each score against the reference values the database publisher
distributes. It can also export the linked system as Brightway datapackages and author
mapping packages in the same format as
[../sentier-mappings/](../sentier-mappings/).

The repository is public because it contains no licensed data. Every background-derived
file is gitignored and blocked by a pre-commit guard, and a licensed user regenerates
those files locally from their own credentials. This page documents only what the public
repository shows. (source: sentier-agribalyse-repo)

**Version documented:** `0.3.0`, from `version` in `pyproject.toml` · **obtained from:**
a clone of `github.com/sentier-dev/sentier-agribalyse` at commit `3d0df56`, dated
2026-09-17 · **as of:** 2026-09-21.

## Install

Python 3.11 or newer, with uv.

```bash
uv sync --extra pardiso
```

The extras are `pardiso` for the recommended sparse solver, `bw` for the Brightway
export, `test` for pytest, `bootstrap` for the one-time background snapshot, and
`llm-api` for the API path of the two model-assisted commands. Installing with pip works
as well.

Activate the guard once per clone, before you touch any regenerated file:

```bash
pre-commit install
```

The runtime dependencies are pandas, pyarrow, numpy, openpyxl, scipy, `bw_simapro_csv`,
`randonneur`, `randonneur_data`, structlog and python-dotenv. The core runtime never
imports `bw2data`: it reads the files under `source/` and `registry/` instead.
(source: sentier-agribalyse-repo)

## What it does

1. **Parses the public SimaPro export** and applies a chain of transforms: deletions of
   aggregated processes, edge-label corrections, unit and label normalisation, parameter
   extraction and re-evaluation. See [classes.md](classes.md).
2. **Links foreground to background** through a tiered registry built from every file
   under `source/`. Tier order decides which mapping wins, and a tier is a row in a
   parquet table rather than a branch in the code. See [classes.md](classes.md).
3. **Scores and backtests.** It builds the matrices itself, registers the headline EF
   3.1 categories, scores every mapped product and compares the result with the
   published reference values, writing a static dashboard. See [commands.md](commands.md).
4. **Exports.** Brightway datapackages plus a standalone importer, randonneur mapping
   packages, review spreadsheets and residual unlinked exports. See
   [datasets.md](datasets.md).

## Datasets

The repository ships the public inputs and the mappings it authors. Everything derived
from the licensed background database is regenerated locally and never committed.

| What | State in the repository |
|---|---|
| The publisher's reference results table | committed, as parquet |
| The public EF 3.1 characterisation factor export and its adapted counterpart | committed, as parquet |
| Curated mapping and correction files, the delete lists, the alias tables | committed, as JSON and spreadsheets |
| The randonneur packages this repository authors | committed, under `source/randonneur_packages/` |
| The SimaPro export itself and the harmonised flow list | local only, not in git |
| Background nomenclature, background exchange amounts, methods inherited against the background biosphere | gitignored, regenerated by a licensed user |
| The built registry, the caches and the Brightway export | gitignored, regenerable |

The detail, including what a licensed user has to regenerate and why, is in
[datasets.md](datasets.md). Licence: MIT for the code; the background database is
licensed separately and never ships here.
(source: sentier-agribalyse-repo)
