# sentier-vocab layout

The repository tree, one line per file or folder, as of commit `ef440c6` dated
2026-09-17. Only the files a reader would open are listed. (source: sentier-vocab-repo)

```
app/sentier_vocab/          the Python package (src layout under app/)
  __main__.py               the CLI: the generate and coverage subcommands
  iris.py                   registry of every published vocab.sentier.dev namespace
  paths.py                  repository paths: data, schemas, output
  schemas.py                LinkML validation of a data file against its schema
  loaders.py                read a YAML or parquet source, write bulk parquet
  rdf_mapping.py            turn a validated record into SKOS triples
  generate.py               build the graph for a source file and write its Turtle
  ordered_serialization.py  deterministic Turtle serializer, for readable diffs
  graph_base.py             base class the external-ontology importers share
  coverage.py               the catalogue behind docs/COVERAGE.md
  errors.py                 the three error types the pipeline raises
  utils.py                  download helpers for the importers
  importers/                transitional importers for external ontologies
    envo.py                 ENVO elementary flows
    qudt.py                 QUDT units and quantity kinds
    open_energy_ontology.py OEO energy products
    combined_nomenclature.py the EU Combined Nomenclature (CN 2024)
    model_terms.py          model terms
    custom_products.py      hand-added products
    geonames_iri_terms.py   geonames places
    generate_mrf_turtles.py material recovery facility parameters
    input/                  the Python literals those importers read
    output/                 Turtle the importers write (deployed, not committed)
  pyst/                     loaders shared with the pyst client
data/<category>/            curated terms, one folder per term type, 13 of them
schemas/                    one LinkML schema per term type, plus common.yaml
  _generated/               Pydantic models derived from the schemas (build artifact)
output/                     generated Turtle; the primary files are committed
scripts/generate.sh         fetch the external ontologies and run the importers
tests/                      pytest suite, with fixtures/
docs/                       Sphinx site, COVERAGE.md and the notebooks in docs/content
dev/                        exploratory notebooks and Fuseki maintenance notes
.github/workflows/          ci.yml, generation-test.yml, python-test.yml,
                            python-package-deploy.yml
```

## Key files

- `app/sentier_vocab/iris.py` is the contract. Every namespace the platform resolves is
  named there, and a data source whose `scheme` is not registered fails generation.
- `app/sentier_vocab/__main__.py` holds the category-to-schema table, the list of source
  file extensions, and the rule that decides which output file a source writes into.
- `schemas/common.yaml` defines the abstract `Concept` class every term type extends:
  the IRI, the preferred label, alternative labels, the definition, the notation, the
  broader term, the SKOS match properties, the source and the status.
- `data/<category>/` is the source of truth for native terms. Nothing is authored in
  `output/`.
- `docs/COVERAGE.md` is generated by `coverage.py` and says, per term type, whether it
  has a schema, whether the data is native or imported, and how many native files back
  it.

## Where the pieces meet

A source file under `data/<category>/` declares the concept scheme it belongs to. The
generator looks up the LinkML schema for that category, validates the file, maps each
record to SKOS triples through the namespace `iris.py` gives it, and writes one Turtle
file per source. The layer that serves those IRIs is fed from `output/` and from
`app/sentier_vocab/importers/output/` by the repository's own workflows.
(source: sentier-vocab-repo)
